# Majority-of-the-Bests (MoB) — arXiv:2511.18630

Local copy: `2511.18630-majority-of-the-bests.pdf` (34 pp). Underpins Cap 1.5 of the
SOTA orchestration engine (`orchestration/dag/best-of-n.ts`, `SelectionPolicy="mob"`).

## Claim

With an imperfect reward, plain Best-of-N does NOT necessarily converge to the
correct answer as N grows (a single lucky high reward on a wrong answer wins).
MoB fixes this: bootstrap-estimate the Best-of-N output distribution and select
its MODE (the answer-value that most robustly wins the per-resample argmax).
Hyperparameter-free, near-zero cost. Reported to beat BoN in 25/30 setups
(5 benchmarks x 3 base LLMs x 2 reward models).

## How Cap 1.5 uses it (and the honest scope)

- Selection happens over the battery's APPROVED survivors only → ADR-068
  fail-closed + deterministic-anchor guarantees preserved (MoB never resurrects a
  killed candidate).
- Grouping key = `candidateHash` (canonical sha256), so identical answers from
  distinct samples accrue to one group (the paper's mode-over-answers).
- Deterministic / replay-safe: bootstrap PRNG seeded purely from `runId|nodeId`
  (fnv1a32 + mulberry32), no `Math.random`, no clock.

Two degeneration conditions (why MoB is OPT-IN, not the turnkey default):

1. Free-text outputs are rarely byte-identical → every group has one member →
   MoB degrades to argmax.
2. The paper's gain assumes a NOISY reward. The ADR-068 anchor is DETERMINISTIC by
   mandate, so on distinct deterministic scores the bootstrap mode == global max
   == argmax. The realised benefit on this engine is the narrower TIE /
   shared-answer case (discrete outputs). Defaulting it on would be a cargo-cult
   near-no-op per ADR-068.

Enable per-run via `PRESTE_DAG_SELECTION=mob`. Default stays `argmax`
(byte-identical to Cap 1).
